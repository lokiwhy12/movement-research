## Purpose
Translate the current recommendation (`pull-factor onboarding` + `ritual map`) into one build-ready v0 concept so founder approval can convert into execution without another full rewrite.

## Experiment name
**24-hour starter loop**

## Plain-English promise
In the first 24 hours, the user should get:
1. **One visible win**
2. **One saved trace of progress**
3. **One obvious next action**

If those three things happen, the product has turned an abstract promise into a felt experience.

## Why this is the right first translation
- It attacks the two earliest leverage points: **activation** and **repeat use**.
- It stays inside normal product behavior — no culty mechanics, no coercive pressure.
- It is simple to explain to a founder, designer, or builder.
- It can be measured with lightweight instrumentation.

## v0 user flow
### Step 1 — onboarding quick win
After signup/onboarding, the product should return one immediate personalized output:
- a sharp insight
- a calibrated reflection
- a suggested next move
- or a simple score/checkpoint

Rule: the user should feel "this already knows enough to help me" within the first session.

### Step 2 — visible saved artifact
The session should produce one thing the user can see later:
- checkpoint
- reflection card
- commitment
- score snapshot
- or named focus item

Rule: the product must leave behind evidence that something happened.

### Step 3 — next-day ritual
Before the user exits, the product should set up one lightweight return action for the next day:
- short prompt
- micro-check-in
- 2-minute ritual
- or one-step follow-up based on today’s result

Rule: the return action must feel easy, specific, and worth doing.

## Success metrics
### Primary
- onboarding completion rate
- day-1 return rate
- day-2 return rate
- completion rate for the first repeat ritual

### Secondary
- share/save rate on the first artifact
- percent of users who reach the next-day prompt
- percent of users who complete the ritual in under 3 minutes

## Failure signals
- onboarding still feels abstract after first session
- users receive output but no durable artifact
- next-day ritual feels like homework instead of momentum
- return rate does not move even when completion rate improves

## Safe translation boundaries
Keep:
- clarity
- momentum
- repeatability
- visible progress

Avoid:
- pressure escalation
- shame loops
- exclusivity signaling
- manipulative streak mechanics
- any framing that feels socially coercive
