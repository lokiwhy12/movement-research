# Movement DNA Program Scope v1

Status: canonical as of 2026-03-15.

Canonical entrypoint / folder map:
- `README.md`

## Core clarification

This project is **not** currently about designing an Apotheosis movement.
This project is **not** currently about choosing a movement name.

The purpose of this lane is to:
- build a database of successful, failed, strange, high-adhesion, and high-control movements
- extract the full-spectrum mechanics that make them work
- decipher the underlying **movement DNA** across cases
- understand the conditions under which movements become compelling, sticky, viral, durable, coercive, or brittle

## Mission

Build a movement-DNA research corpus and analytical model.

The outputs should bias toward:
- target packets
- taxonomy work
- primitives libraries
- mechanism matrices
- ladder / status / ritual / recruitment / retention analysis
- success-condition and failure-condition models
- comparative case notes
- a searchable database of movement mechanics

The outputs should **not** assume:
- that the end goal is an Apotheosis-branded movement
- that the immediate goal is to design a launchable movement
- that the current research should be translated directly into product or community design

## Downstream application boundary

Loki has now named the downstream movement project **Monolith**.

The movement-DNA database built here is intended to become an inspiration/input layer for Monolith later — especially for:
- structure
- stratagems
- ritual architecture
- ladder/status design
- language systems
- recruitment and retention mechanics

However:
- **APO-MOVE remains a research/database lane**
- Monolith design is a later translation layer, not the current deliverable
- analytical docs should clearly distinguish between **observed mechanics** and **possible Monolith applications**

## Full-spectrum analysis dimensions

Each movement case should be analyzed across as many of these dimensions as possible:
- identity construction
- initiation / conversion path
- doctrine / language / compressed vocabulary
- ritual / event / container design
- curriculum / ladder / status economy
- recruitment / referral loops
- retention / belonging / social reinforcement
- monetization / ascension / commitment escalators
- authority structure / founder role / operator role
- pressure mechanisms / shame dynamics / coercive edges
- sexuality / intimacy dynamics where relevant
- distribution / memetic spread / timing conditions
- durability / succession / decay / failure modes
- what is strategically useful to understand

## Handling older artifacts

Artifacts created under the earlier “build a movement / blueprint” framing should be treated as:
- historical analytical artifacts
- provisional synthesis attempts
- **not** the current canonical scope

Specifically:
- `docs/targets/movement-blueprint-v0.md`
- `docs/targets/movement-blueprint-v1.md`

These may still contain useful extracted thinking, but they are now superseded as the governing frame.

## Operating rule

When in doubt, ask:

**Is this helping build the movement-DNA database and decode why movements work?**

If yes, it belongs.
If it is prematurely designing a named movement, it does not.
